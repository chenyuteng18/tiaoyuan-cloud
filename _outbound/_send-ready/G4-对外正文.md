## 三、首要问询事项（共 13 条，请逐条对应编号回复）

以下 13 条是我方当前**最优先需要确认的技术事项**（未获答复前，我方无法冻结数据采集与接口设计）。**回复时请直接引用「问题 1」…「问题 13」的编号。**

**问题 1 —— SDK 支持的宿主环境**
请确认贵司 SDK 支持的宿主环境：
**(a)** 是否提供 Android（`.aar`）/ iOS（`.framework`）原生 SDK？
**(b)** 是否提供 React Native / Flutter / uni-app 的**原生插件封装包**（现成的桥接层）？
**(c)** 若 (b) 不提供，**是否开放原生 SDK 源码 / 头文件供我方自行封装**？封装工作量的归属与技术文档支持如何安排？
**(d)** 请明确确认：能否在**微信小程序**环境中使用该 SDK？（我方理解当前文档未声明小程序支持，请书面确认。）

> 补充说明：请贵司在答复时**区分「编译到 App 端」与「编译到小程序端」两种情形** —— 前者为原生运行时（可集成，但需插件封装），后者不是。仅回答「支持 uni-app」不足以回答「能否编译到小程序端运行」。

**问题 2 —— 佩戴检测与有效测量时长**
SDK 是否提供「**佩戴检测（离腕 / 佩戴状态）**」与「**逐日有效测量时长**」两项数据？请给出对应的**字段名、单位、精度、统计粒度**（按日 / 按小时 / 按次）。

**问题 3 —— 原始采样还是预聚合数据**
SDK 回传的是**原始采样数据**，还是**厂商侧预聚合后的数据**？我方能否获取**原始 PPG / 加速度 / RR 间期**数据？若能，对应的**采样频率**是多少？

**问题 4 —— 无数据时的返回语义与状态码**
当某一天无数据时，SDK 是返回明确的「**无记录**」标记，还是**静默不返回**任何内容？是否返回「**未佩戴 / 未同步 / 同步失败 / 电量低**」等**状态标识与原因码**？

**问题 5 —— 字段级 Schema 与 7 类数据确认**
请提供**字段级 Schema**（字段名 / 单位 / 类型 / 采样频率 / 时区），并**逐项确认**下列 **7 类数据是否原生提供**：睡眠、步数、心率、**静息心率**、**压力**、血氧、运动类型。
其中「**运动类型**」请给出**全部 16 种的枚举值**；另请确认：**每条记录是否提供起止时间戳**。

**问题 6 —— 静息心率与压力的可交付性**
**静息心率**与**压力**两项是否为 SDK **原生提供**的数据？若否，是否提供**可用于推导的底层数据**（心率时序 / 心率变异性 / RR 间期）？
另请**书面确认**：贵司官网宣传的「**心率变异性分析、情绪检测**」，是**可通过 SDK / API 获取的能力**，还是**仅在厂商 App 内展示**？

**问题 7 —— 鉴权与配对机制**
设备的鉴权与配对机制如下，请逐项确认：
**是否必须经厂商服务器 / 厂商账号完成激活？能否在第三方 App 内完成完全本地配对？配对密钥由哪一方签发？是否要求 App 常驻后台？**

**问题 8 —— 设备绑定 / 解绑事件与字段**
请提供设备绑定与解绑相关的事件与字段：**`device_unbind`（解绑事件）**、**`unbind_reason`（解绑原因）**、**绑定日与解绑日的时间戳**、**设备唯一 ID**。
并请确认：**「解绑」是否为 App 内可正常上报的动作？**

**问题 9 —— 电量 / 充电状态与充电提醒时间**
请提供「**电量状态 / 充电状态**」，以及「**充电提醒发送时间**」字段——**`charge_reminder_sent_at`**。

**问题 10 —— 是否开放标准 BLE GATT 供第三方客户端直连**
GTL1 是否开放**标准 BLE GATT 服务**（自定义 Service / Characteristic），供**第三方客户端**（含**微信小程序的 `wx.*Bluetooth*` 系列接口**）**直连读取**？
若开放，请提供：**GATT Profile / UUID 清单**、**配对与鉴权方式**（是否绑定厂商账号 / 密钥）、**数据帧格式**、**是否需厂商 App 先行激活**。
若**不予开放**，请明确答复「**仅可通过厂商 App 或厂商云**」。

**问题 11 —— 佩戴状态字段的无效值语义**
`isWear` 返回无效值（`-1`、`255`）的**触发条件**是什么？是否提供「**设备异常 / 传感器失败**」的**原因码**，以把「**设备异常**」与「**客户脱腕**」两种情况区分开？

**问题 12 —— 逐日历史接口的「无数据」语义**
**逐日历史接口**在「**该日确实无数据**」时，是返回**明确的「无记录」标记**，还是**静默返回空数组**？若为静默返回，能否**补充一个明确的标记位**？

**问题 13 —— 小程序场景下的强制激活问题**
在**微信小程序**场景下，是否**必须经厂商 App / 账号激活**？能否在**不安装即米 App 的前提下**完成**配对与鉴权**？
