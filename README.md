## 📌 TL;DR

把线下"禁忌排查 → 评估 → 出方案 → 审核 → 签协议 → 调理 → 再评估"的**人工闭环**，做成**跨门店不可绕过的系统状态机**：4 道门禁由系统硬阻断而非人工提示，判定阈值总部集中配置、门店只读，客户属于品牌可跨店通兑。

一句话定位（**v1.8 已修正**）：**我们不是"判定该不该退"的引擎，而是"让每一次协商都有据可依"的系统。** 对外卖点是三项可计量能力 —— **证据链完整率 / 周期复评完成率 / 争议一次举证通过率**；效果判定本身已下调为**对内能力**。

**本会话最实质的转向**：业务方在 2026-09-16 给出「退款字样不在客户端、调理师端显示」这条规则，**推翻了原设计（CS-3）**。产品形态从"把退款入口搬到客户端、让门店拦不住"翻转为"**退款是内部事务，客户开口 → 调理师原样转交 → 经络师判定**"。这条转向连带产生**四种失效模式（R4a/R4b/R4c/R4d）**与一个新硬需求 **P0-19 代录纪律**。

⚠️ **旧枢纽论点必须换掉，不只是隐藏入口**：原设计的核心论证是"只有把入口移到客户端，才能绕开门店拦截诉求"。入口取消后，**代录人仍然是门店侧的人——原冲突并未消失，只是换了位置**。现行兜底是三件套：**代录纪律**（当日建单）+ **`requested_at` / `created_at` 分离**（延迟可测）+ **抽查比对**（客户回访 vs 工单时间戳）。**它比原设计弱**，残余风险已登记为 R4c 与 R13d，**不可缓解、只能被观测**。凡仍写着"客户自助提交 / 客户端自助直退 / SLA 双向可见"的地方，都是 v1.9 已推翻的残留。

**最后一块拼图来自业务方自己的 05 表**：05 表 §二 原文早已写着「若客户出现明显不适、症状加重或**要求调整**，应立即备注并反馈经络师」—— 所以调理师端转交**不是新需求**，而是**把 05 表已有的书面义务搬进系统**（对外口径统一为此表述）。⚠️ **但"复用 ≠ 降价"**：省掉的是门店与客户的**学习成本与阻力**，**不是研发工时**（省下的表单 UI 成本被规则引擎成本抵消）——**省的是"人"，加的是"代码"**。

**手环采集模式已定（2026-09-19 业务方拍板）**：原话「**先做小程序吧，必须保证打开小程序自动获取智能手环数据。**」→ **载体 = 微信小程序（不新增原生 App）**，**采集模式冻结为 config #44 的 `M-WX-FG`**：**客户打开小程序即自动发起同步（无需点击）**。**「保证」的边界须说清**：✅ 可保证「打开即自动触发」与「失败可见、且失败不冤枉客户」；❌ **不可保证「打开必同步成功」**（6 类不可控变量：未开蓝牙 / 拒绝授权（iOS 不可逆）/ 手环没电 / 被厂商 App 占用连接 / 停留不足 / 超留存窗口）。**实质改进 = 设备端历史补拉**（13 条逐日接口可按日期回捞）→ 把"每天必须打开"降为"**每 N 天内打开一次**"；**但"补拉必然跨 `f*`≈91.5%"不成立**（`N` 与 `s` 均未取证）。**若 A3 长期不达标 → 按 `applicable=False` 重归一 → 依从性模型退化为三维**，**这是"零安装"的真实定价，须写进裁定书**。详见 PRD **§2.8.7**。

## ✅ 七个最重要的设计决策

1. **效果判定 = 门槛制，不是加权总分**
   `有效 = 核心指标在「基线→周期」同源测量下改善/稳定 且 AS ≥ 0.8`。手环数据**只进依从性、绝不进效果主判据**；结构性缺失（未同意佩戴）不扣分，行为性缺失才扣分。（04/06 表原文"不作为单方判定依据""未佩戴不得作为客户不利依据"已反向印证）

2. **四道门禁一律系统级硬阻断**（后端 403，非前端提示）
   禁忌通过 / 知情同意已签 / 协议已签 / 方案已确认且在有效期。配套"判定即动作"——"依从达标但无效"由系统自动触发重定方案，不依赖门店主动发起。

3. **准入顺序：禁忌筛查 → 建档 → 签知情同意书**（业务方澄清更正）
   有禁忌者**只留筛查记录、不建档**；客户拒签时停在 `PROFILED` 并记录原因——**先建档的好处是拒签也留得下凭证**。状态机 14 态（11 活动 + 3 终态）。

4. **退款拆两条通路**（v1.8 核心修正）
   **履约类**（未交付/错交付/停交付）走**规则直退**（未消耗次数 × 单次均价，系统自动算）｜**效果类**（改善不明显/与期待不符）走**协商**（人工在环、全程留痕，**不允许系统自动出结论**）。理由：全行业把退款钉在交付状态上，**"无效退款"在境内属违禁表述且落纸即败诉**（详见裁定单 Q10）。**业务方原文依据**：「经络师再根据客户得数据看是否同意退款事宜」。

5. **退款是内部事务，客户端与调理师端都不露出**（v1.9 · 业务方规则，原 CS-3 已作废）
   业务方原话：「退款字样在客户端、调理师端都不显示，只在经络师和管理员端显示操作。」
   可见性矩阵（**两项曾悬空的 ❓ 已于 2026-09-16 全部裁定**）：

   | 角色 | **端形态** | 退款可见 | 备注 |
   |---|---|---|---|
   | 客户 | **小程序** | ❌ | 无字样、无入口、**包内无退款接口与文案资源**（构建期扫描命中阻断） |
   | 调理师 | **APP** | ❌ | 但**有中性转交动作**（= 05 表已有义务搬进系统，见决策 6）；**退款能力不在本角色加载** |
   | **门店客服** | **无端（不使用系统）** | **❌ 完全不可见** | 2026-09-16 裁定；**无账号、无端、不代录、无任何录入/转交入口**（硬边界）→ **R4c 客服侧为结构性不可观测、不可缓解** |
   | 经络师 | **APP** | ✅ | 业务方指定 · **代录人**；退款能力**仅在本角色下加载** |
   | 门店负责人（管理员） | **Web** | ✅ | 业务方指定 · **代录人 / 审批** |
   | **区域督导** | **Web** | **✅ 可见** | 2026-09-16 裁定；可见辖区工单与异常名单，**不审批**；是超时升级第一跳 |
   | 总部运营 | **Web** | ✅ | 可见 + 稽核 |

6. **传递链必须闭环：调理师端「记录异常 / 反馈经络师」**（v1.16 定 · v1.17 改为复用 05 表备注列）
   业务方原话：「客户端也是没有退款字样得，**客户只会和调理师说，然后调理师告诉经络师**，经络师再根据客户得数据看是否同意退款事宜。」
   → **客户开口的第一句说给调理师，而调理师端也不显示退款字样** —— 若不给落点，"告诉"这一句在系统里就是**一段空白**。业务方 **05 表 §二** 已有「立即备注并反馈经络师」义务与 `异常/备注` 列，故**不新建入口**：复用备注列 + 结构化标记位 + **自动路由生成转交待办**（全链路无"退款"字样，**原话 append-only 不可编辑**，**不生成退款工单**）。
   **四种失效模式必须分清**：**R4a 结构性**（客户端无入口 → 观测权归零）／**R4b 执行性**（代录人拖延或改写原话，**仍留下记录**）／**R4c 传递性**（客户认为他已提出过，**而系统里什么都查不到** —— 正是中山中院那类判词的对立面）／**R4d 静默丢失**（**漏打标记 / 路由规则未命中 → 转交事件根本没发生**；前三条都假设"转交已经发生"，只有它连事件都没有，**v1 期间不可观测、🔴 未缓解**、检测手段 = P1-04 派生查询）。
   **R4c 分侧定性**：**调理师侧 = 已缓解（条件 = 转交动作 + 转交段独立计时；缺一则退回"未缓解"）** ／ **客服侧 = 结构性不可观测（客服无系统账号）→ 已接受风险、不可缓解（系统侧）／可部分缓解（SOP 侧，手段唯一 = C-1-1）**〔v2.2 由"残余风险（未观测）"升级〕。**任何"给客服开账号/开端"的提议 = 变更业务裁定**，触发 P0-19 返工条款 + 重走 `refund_visibility` 冻结，**不得按"体验优化"处理**。**不得写成一个全局标签**，且**"已缓解 ≠ 免罚"**（开工后改口仍计 P0-19 返工代价）。

7. **24h 代录计时的锚点 = 最早且可核实的时间**（v1.17）
   `requested_at` = min{ 客户可自证时间（须附凭据引用）, 调理师转交提交时间 } —— **24h 从它起算**；`requested_at_claimed` = 客户主张的时间，**仅留存、永不进计时**（**配守卫性回归断言：任何超时判定引用它即验收失败**）；`requested_at_source` 标来源。**「最早」必须锁在「可核实」集合内**：允许不可核实的主张进计时，等于自证"时间戳可随手改"；只留"最早"又会放过"门店未记录、客户能自证更早"。

## 🔍 本会话的三个关键结论（相对上一版交付包的实质性变化）

1. **「无效退款」从"护城河"降级为"合规风险"**
   竹溪县市监局 2026-09-03 合规提示明文禁用该表述（适用非医疗机构）；持《医疗机构执业许可证》者另有《医疗广告管理办法》第七条禁止"隐含保证治愈"；落纸则海南乐东法院 2024 判全额退、武汉蔡甸区法院 2025 判退一赔三；而"概不退款"同样无效（江苏仪征案）。**全行业无一成规模玩家把退款锚在效果上。**

2. **量表量程统一为 0–4，且"不是壁垒"**
   0–4 是 02 表原生量程（零迁移）；若迁就 05 表的 0–3，重度端真实改善会被吞成 IR=0%。但 224 题与国标 GB/T 46939—2025（27 题 / 4.23 分钟）相比属**可复制资产**——真正的稀缺物是"同一组客户在同一把尺子上、连续多周期、带完整履约记录的真实数据"。

3. **低龄两组 56 题是内容层硬缺陷（统计方法补救不了）**
   题面为正向"健康状态"措辞，评分标准却是"不适程度"，会得出"越调理分越高"的荒谬记录。已列为**题库入库前的阻断式校验项**（P0-18），未完成改写与逐题签核前，对应分龄组建档与基线评估入口返回 403。
