## A. 用户洞察（来源：瑞思 · 用户研究员）

### A1. 角色画像与痛点（门店侧 5 类）

| 角色 | 核心 JTBD | 最大痛点 | 数字化诉求 |

### A3. 三个反直觉洞察（含依据与置信度）

**① 「无效退款」是最大成交杠杆，也是最大亏损敞口 —— 它不该是售后流程，而应是销售与风控的共同契约。**
依据：Andreoni《Satisfaction Guaranteed》(AEJ: Microeconomics) —— 可被执行的满意保证显著提升买方信任与成交效率；不可执行的保证下仅 17% 的退款请求被兑现（AEA Research Highlights）。推论：若"无效"不写死、不对外可验证，该承诺既拿不到信任红利，又会在争议时全额赔付。
置信度：**中**（机制可信，门店服务业的本土外推未验证）。

**② 手环是自愿的，任何硬性依赖手环数据的判定必然失效 —— 依从性底线必须由小程序填报 + 调理师代核兜底。**
依据：Hermsen et al., JMIR mHealth 2017（n=711）：Fitbit 使用指数衰减，100 天留存 73.9%、320 天仅 16.0%，平均使用 129 天；停用主因设备故障/没电/丢失占停用者 56.7%（PMID 29084709）。15~45 次、跨数月的疗程大概率落在衰减区间。
置信度：**高**。

**③ 把"每 7 次评估"做准，比把"15~45 次全周期"做全更值钱 —— 首周期是唯一止损窗口。**
依据：文档明确"首周期 7 次后主动评估，不达标 → 不经挽留主动终止退款"，这是全流程唯一"系统主动止损"节点。〔推断〕前 7 次判定质量直接决定退款成本。
置信度：**中高**。

### A4. 设计启示 8 条（可直接作为 PRD 设计约束）

1. **必须**把"禁忌通过 / 知情同意书已签 / 调理协议已签 / 方案已确认且在有效期内"做成四个**系统级硬闸门**，未过闸不可下发设备参数、不可记录服务次数；提示性校验一律不算数。
2. **必须**把"无效"写成可执行公式（指定核心指标 + 阈值 + 依从性门槛 + 次数窗，默认 7 次），并同时出现在《调理协议书》与客户小程序；**必须不能**把判定权完全留给人。
3. **必须不能**默认手环数据可用：判定引擎须支持"手环缺失"降级模式，以小程序填报 + 调理师到店代核为主证据，评估页显式暴露缺口天数。
4. **必须**实现方案"提交—审核—驳回意见—版本留痕—变更后强制重签"全闭环，审核人与出方案人权限可分离；**必须不能**允许同一账号无痕自助通过。
5. **必须**把周期评估从"人想起才做"改成"次数触发 + 预填数据 + 四分支强制路由"，判定依据必须落库。
6. **必须**把退款做成工单：原因码必填、挽留记录必填，四种结局全部强制归档；**必须不能**允许"未记录原因即结案"。
7. **必须**让每日填报 ≤30 秒并给即时反馈，连续漏填双推客户与调理师待办；**必须不能**把填报设计成表单填写。
8. **必须**建立门店级设备台账与参数模板，参数下发与方案版本绑定并留痕；**必须不能**把设备型号硬编码进流程。

### A5. 关键用户故事 5 则（含验收要点，摘录）

- **US-1 禁忌门禁**：未通过排查 → 建档/出方案/下发参数**系统级硬阻断（非提示）**；题目答案操作人时间戳全量留痕可导出；禁忌项可配置，改题后对在服客户触发重筛。
- **US-2 方案回炉**：审核人与出方案人可配置为不同账号；同人自助通过需二次确认并留痕；驳回必填意见、版本号递增、历史可对比；变更后自动生成"客户重签"任务，未重签则执行页锁定。
- **US-3 每日填报**：全点选无开放输入，首屏可完成；提交即回显"本周 X/7 天 + 与上周对比 + 一条可执行建议"；连续 2 天漏填同时推客户与调理师待办，调理师可代核/补录（须标注来源）。
- **US-4 周期评估**：按服务次数自动触发（7 次可配置），支持手工提前触发；预填三类数据并显式标注"手环缺失 N 天"；四分支选择后自动路由，分支与依据必须落库。
- **US-5 退款挽留**：退款生成工单、原因码必填，未经原因分析不可进入终止；首周期双不达标 → 系统主动推"建议主动终止退款"，不经挽留；四种结局全部强制归档。

## B. 指标与判定引擎（来源：数析 · 数据分析师，最终对齐版）

### B1. 北极星指标：有效结案疗程数 ECC

- **定义**：自然月内完成「归档结案」，且同时满足【周期评估=稳定/改善】+【未触发无效退款】+【依从性可分级说明】的疗程数。
- **公式**：`ECC = Σ 疗程 ([已结案] × [效果 ∈ {稳定,改善}] × [退款=否])`
- **口径边界**：按结案时间归月；跨月疗程不重复计；同一客户多疗程分别计数。
- **为何是它**：唯一同时强制【真实改善 + 完成全周期 + 无退款争议】产出的指标，把效果与风控绑进北极星。
- **反博弈**：① 不用续费率/GMV（诱导压单、拒退）；② 效果判定双轨（人工录入 + 系统自动计算），防自我放水；③ 依从性对"未同意佩戴"不计分，防变相强制手环。

### B5. 依从性模型 AS v2（4 维 · **门槛制，非加权总分**）

| 维度 | 口径 | 权重（建议值，需真实校准） |
|---|---|---|
| A1 到店履约率 | 实际到店 / 应到店 | **0.40** |
| A2 小程序每日填报率 | 实填天 / 应填天 | 0.30 |
| A3 手环有效佩戴率 | 有效佩戴天 / 应戴天（仅"同意佩戴者"适用） | 0.20 |
| A4 生活方式执行核对达标率 | 到店间隙核对达标 | 0.10 |

```
AS = Σ(w_i × s_i) / Σ(w_i)      # 仅对 applicable=True 的维度求和
缺失值分流（必须严格区分两类，不可合并）：
  结构性缺失（未同意佩戴手环 - 合规自愿）
        → 该维度 applicable = False，权重重归一化，不计扣分
  行为性缺失（同意却漏戴 / 漏填 / 未到店）
        → applicable = True，缺失天按 0 计入分母
护栏：应填天数 < 7 → AS 标记"样本不足"，不得用于退款门禁
门槛：AS ≥ 0.8 为达标（建议值，需真实数据校准）
```

**定调（数析最终结论）**：
- **效果判定为门槛制，不是加权总分**：AS ≥ 0.8 仅作**门槛**，**核心指标为主判据**，二者不相加。
- **手环定位收紧**：手环**只进"依从性"输入，绝不进"效果核心指标"主判据**；指标卡需新增**「数据完整度 / 缺口天数」**字段 + 覆盖率不足自动降权护栏。
- **结构性与行为性缺失必须分流**：未同意佩戴（合规自愿）**不计扣分**；同意却漏戴/漏填（可避免行为）**必须扣分**。否则依从性会系统性歧视"如实选择不戴"的合规客户。

**效果公式（可直接写入 PRD 与对外文案）**：
> **有效 = 核心指标在「基线 → 周期」同源测量下「改善或稳定」 且 AS ≥ 0.8；否则按 D5 四分支处理。**

### B5-2. 两条合规硬约束（建议写入 PRD）

1. **核心指标「测量可比性」前置**：基线点与周期点必须**同源测量**（同测量人 / 同工具 / 同时点）。若不可比 → **效果判定挂起，转人工**，不得直接判定。依据：DTx 监管趋势（NMPA 已批 235 个 DTx 器械，96.6% 需处方），疗效证据正在成为准入前提。
2. **穿戴字段 Schema 照华为 Health Service Kit**：睡眠 / 步数 / 心率 / 静息心率 / 压力 / 血氧 / 运动类型；降级路径严格按源文档 D2（手环自愿）执行。


### B6. 效果判定规则表

| 条件（可自动判定部分） | 结论 | 系统动作 |
|---|---|---|
| 核心指标 ∈ {稳定,改善} 且 AS ≥ 0.8 | 稳定·改善 | 维持原方案，生成下一周期 |
| AS < 0.8 | 依从不足 | 强化生活方式干预+追踪任务，推送提醒 |
| AS ≥ 0.8 且核心指标无改善 | 依从达标但无效 | 自动提醒经络师重定全新方案；设备路由（秦皇岛→杠2，其他→现有） |
| 经络师录入标签 ∈ {高危,新发,同病} | 全面评估 | 生成全面评估任务 → 新方案 → **回炉审核 + 客户重签** |
| 条件不满足 / 数据不足 | 人工复核 | 挂起，待经络师决策 |

**无法自动判定、需人工录入**：①「高危/新发/同病」属临床判断；②基线评估与核心问题诊断（症状/体征需结构化为标准字段）；③不同指标类型"改善"的可比映射；④禁忌症最终判定（合规需人工签核）。

### B7. 首周期单列三指标 + 合规过程指标

- 首周期转化率、首周期主动止损率、**首周期误判率**（人工复核口径，建议值）
- **变更后重签及时率**（方案变更后 24h 内重签比例，建议值）
- 数据完整度/缺口天数字段（覆盖率不足自动降权）

### B8. 行业数据依据（供商业论证引用）

1. 2023 年中国中医养生保健行业市场规模约 2200 亿元（养生馆约 500 亿），预计 2027 年约 3500 亿元（中研普华，2024）。
2. 2024 年中医养生保健市场规模约 4500 亿元；美团 2025Q1 中医养生订单量同比 +67%，90 后用户占 58%（中研普华，2025）。
3. 可穿戴依从：RA 患者 84 天研究，每日 ePRO 依从率 57.2%，智能手表数据达标率 81.7%，综合依从 52.9%（Nowell et al., JMIR Human Factors, 2023）。
4. 移动健康 APP 30 日留存：健康健身类仅 3%（AppsFlyer 2023）/ 8%（Adjust）；国内医疗健康 APP 普遍 <10%~18%（艾瑞/QuestMobile 2023）。
5. 基层慢病随访：高血压规范管理率约 72%~86%、随访率 96%~99%（多地 2023 年基本公共卫生服务决算）。

## C. 多门店 SaaS 平台层设计（来源：主理人综合，含数析 SaaS 增量）

### C1. 租户与组织模型

```
tenant (连锁品牌 · 调元堂)
  └── region (华北区 / 华东区 …)        仅汇总视图与督导授权，不产生业务数据
        └── store (秦皇岛店[直营] / 唐山店[加盟])   业务发生的唯一场所
              ├── staff (店长 / 调理师 / 经络师 / 客服)
              └── device (杠2 / 现有设备)  ← 设备型号是门店级属性
customer (归属 tenant，不属于 store)
  ├── owner_store     首次签约门店
  └── serving_store   本次服务门店
```

- 全部业务数据带 `tenant_id`，**存储层隔离**（不依赖应用层过滤）。
- **客户属于品牌**：可在任意门店接受服务，这是跨店通兑成立的前提。

### C2. 权限矩阵（关键行）

| 能力 / 数据 | 总部 | 区域 | 门店 | 加盟商 |
|---|---|---|---|---|
| 禁忌/诊断明细 | ✅ | ✅ | 本店 | 本店 |
| **判定阈值配置** | ✅ 唯一 | 只读 | 只读 | 只读 |
| 效果判定分支明细 | ✅ | ✅ | 本店 | **不可见** |
| **稽核与放水信号** | ✅ | 辖区 | **不可见** | **不可见** |
| 退款受理与挽留 | ✅ | 辖区 | 本店执行 | 本店执行 |
| 跨租户数据 | 全部禁止（存储层隔离） | | | |

> "稽核信号对门店不可见"是硬要求：被稽核方能实时看到自己的放水指标，指标会立刻被博弈掉。

### C3. 总部管控 vs 门店自治边界

**必须集中（总部唯一可改）**：依从性达标阈值、效果判定分支规则、退款门禁规则、禁忌症清单、周期与评估节奏（每 7 次 / 15~45 次）、标准方案模板库。
**可放权**：预约排班规则（门店）、提醒频次与话术（门店，模板总部提供）、本地设备参数微调（门店，须入台账留痕）、员工考核权重（区域，须版本审计）、门店展示信息（门店）。
**统一机制**：任何配置变更写「变更日志（谁改/何时/为什么/影响哪些在服务客户）」，且默认**不回溯**已生效判定。

### C4. 跨店通兑与责任归属（数析结论）

| 要素 | 规则 |
|---|---|
| 客户 owner | 首次签约门店；跨店服务记为「借调」，依从性与 NPS 回 owner 店 |
| **ECC 归属** | 以**结案门店**为主计；若 ≥30% 次数在他店完成，按**各店已服务次数占比拆分**（允许小数） |
| **退款率** | 分母与主责归结案门店；退款损失按各店服务次数占比**分摊**为各店退款成本 |
| 转店动作 | 必须走**系统转店工单**，禁止私下转 |

**设计理由**：若 ECC 全归结案店 → 门店抢结案、中途截客；按次数拆分让早段服务店也分润，机制性抑制截客。若退款全归受理店 → 门店推诿拒收；损失分摊后，任何一店夸大疗效都要承担退款成本，从源头抑制过度承诺。

**跨店异常检测**：同一客户 30 天内服务门店数 ≥2 标记 / >3 冻结 → 转店工单审查；单客户跨店服务次数占比 >30% → 反刷次数审查。

### C5. 门店健康度 HSI（可排名）

`HSI = Σ(权重ᵢ × 归一化指标ᵢ)`，各指标 min-max 归一到 0~100。

| 纳入指标 | 权重（建议值，需真实校准） | 方向 |
|---|---|---|
| ECC（绝对量+环比） | 25 | ↑ |
| 退款率 | 20 | ↓ |
| 无效退款触发率 | 15 | ↓ |
| 协议签署合规率 | 10 | ↑ |
| 方案一次审核通过率 | 10 | ↑ |
| 小程序填报率 | 10 | ↑ |
| 稽核问题数 | 10 | ↓ |

分层线：绿 ≥80 / 黄 60~79 / 红 <60（建议值）。**护栏**：当月结案疗程 <20 的门店强制标注「样本不足」，不参与排名。

### C6. 稽核与反博弈信号（**门店不可见**）

| 信号 | 口径 | 阈值建议 | 处置 |
|---|---|---|---|
| 放水·判定宽松度 | 经络师"稳定/改善"占比 ÷ 全网均值 | >1.3 | 抽检近 30 天判定留痕 |
| 放水·判定过快 | 评估提交 → 判定落库 间隔 | <5 分钟 | 强制二次复核，冻结自动判定 |
| 放水·方案雷同度 | 方案文本/参数组合重复率（SimHash） | >85% | 模板滥用审查，回炉重出 |
| 规避退款·受理延迟 | 退款申请 → 受理确认 时长 | >48 小时 | 自动升级至区域 |
| 规避退款·原因集中 | "体验类"退款原因占比 | >60% | 原因真实性复核 |
| 规避退款·挽留缺省 | 挽留发起率（发起/应发起） | <50% | 核查是否漏配挽留流程 |

### C8. 交付形态与计费（产品建议，需商业侧确认）

- **自用优先**：先在自有连锁跑通，形成标准作业与数据资产。
- **再对外 SaaS**：把"禁忌门禁 + 审核流 + 周期评估 + 退款门禁"打包为行业标准能力。
- 计费口径候选：按门店数 / 按活跃客户数 / 按疗程结案数；建议**门店数 + 疗程量阶梯**，与客户价值挂钩。

### D2. 功能对比矩阵（关键结论）

**我们具备、且全部 8 家竞品都不具备的：**

- **多级方案审核流**（8/8 ❌ 或 ⚠️，无一家具备）
- **禁忌症筛查硬门禁**（8/8 ❌ 或 ⚠️）

### D4. SWOT

- **S**：① 唯一把"无效退款"做成可审计判定规则；② 源流程已含四道硬门禁，产品化阻力小；③ 门店真实 15~45 次长周期服务数据是竞品没有的资产；④ 执行与评估角色天然分离，权限模型清晰。
- **W**：① 无品牌与客户基础；② 中医疗效判定缺循证标准，规则易被质疑主观；③ 依赖手环与填报，数据缺失风险高；④ 设备参数下发受制于厂商接口开放度。
- **O**：① 服务过程与风控层是空白；② 穿戴渗透率上升使依从性可量化；③ 监管趋严抬高门槛，先合规者获利；④ 连锁化率提升，总部需要可复制 SOP 系统。
- **T**：① 博卡/有赞向下加健康模块、ABC 向上加疗程管理；② 门店嫌流程重，私自绕过系统；③ 无效退款条款可能引发集中索赔；④ 中医疗效证据不足的合规与舆情风险。

### D5. 差异化机会 5 条

1. **无效退款判定引擎** — 空白：所有竞品都不碰"承诺—判定—赔付"闭环｜能赢：同时握有核心指标+依从性+穿戴填报三类数据｜风险：判定规则主观，须人工终审+全程留痕。
2. **服务过程强门禁编排（四道硬卡）** — 空白：门店 SaaS 只有开单核销，无临床风控｜能赢：源流程已定义门禁｜风险：流程过重导致执行率下降，需移动化与极简交互。
3. **次数驱动的周期评估引擎** — 空白：美业按次卡核销、慢病按日历随访，无人按"服务次数+指标"双触发｜能赢：刚需业务规则，竞品改造成本高｜风险：门店周期口径不一，需配置能力支撑。
4. **门店级设备台账 + 参数一键下发** — 空白：设备厂商只管自家云，门店 SaaS 不碰设备｜能赢：唯一打通"方案→设备"的角色｜风险：厂商无标准协议，需适配层 + 降级人工方案。
5. **敏感个人信息合规 + 脱敏案例资产化** — 空白：健康档案沉睡在 HIS｜能赢：结案《调理效果确认》天然产出案例资产｜风险：PIPL 单独同意获取难，脱敏规则需法务共建。

### D6. Battle Card：vs ABC 诊所管家

- **Q1「ABC 已服务多家中医馆，还带连锁经营，为何换你们？」** → ABC 管诊所运营（挂号/收费/发药/进销存/划扣），我们管疗程服务的履约与风控。同一位客户在 ABC 是一张收费单，在我们这里是一条有门禁、有审核、有效果判定的 15~45 次服务链路。两者可并存：ABC 管钱和药，我们管服务过程与退款风险。
- **Q2「ABC 也有慢病管理和随访，不就是你们的周期评估？」** → 随访是按时间排的计划（谁随访、随访什么）；我们的周期评估是**按服务次数触发的判定引擎**——每 7 次自动汇聚三类异构数据，输出四分支，直接联动退款门禁与方案回炉审核。随访是记录动作，我们做判定与责任闭环。
- **Q3「ABC 能对接 95% 检查检验设备、结果自动回传，你们的下发有何不同？」** → 那是**数据上行**（仪器→系统），我们是**参数下行**（系统→治疗设备）：审核通过后按门店设备台账自动匹配型号（秦皇岛=杠2 / 其他=现有）一键下发，消除人工抄参偏差。门店侧无人覆盖。

### D8. SaaS 商业模式对比与自用/外售判断（竞析补充件）

| 厂商 | 计费方式 | 获客路径 | 价格（公开口径） |
|---|---|---|---|
| 博卡 | 年费为主，按门店数+模块阶梯 | 直销+渠道代理，美业 20 年存量 | 第三方称 1500~3200 元/年，另有"买断制"说法，**两说冲突，待核实** |
| 有赞 | 版本年费 + 按门店增购 | 上市公司品牌 + 公域团购核销沉淀私域 | 官网：基础版 6800 / 专业版 12800 / 旗舰版 26800 元·年（含 1 店），每增 1 店约 +3000 元/年；第三方渠道报 1000~3500 元/年，**成交价差异极大，待核实** |
| ABC | 基础功能免费 + 增值模块付费 | 诊所/中医馆地推，案例背书 | 未公开定价，**待核实** |
| 妙健康 | 不向门店售卖：数据平台授权 / SDK 服务费 / B2B2C 方案 | 客户是保险、体检、银行、手机厂商 | 未公开 |

**判断（竞析结论）：Phase 1~2 坚定自用，不要一开始就做对外 SaaS 生意。**
1. **客群太窄、年费天花板低**：有赞旗舰版 2.68 万/年 + 3000 元/店，一个 20 店连锁全年付费不到 10 万，扣获客/实施/定制后单客户毛利撑不起 SaaS 模型。
2. **核心价值卖出去即失守**：判定引擎、退款门禁规则、脱敏案例库都依赖门店真实经营数据沉淀，外售等于把护城河交给同业。
3. **渠道战打不赢**：博卡/有赞有 20 万+ / 30 万+ 门店存量与极低边际成本。
4. **自用能长出自带壁垒的资产**：稀缺的是"15~45 次长周期 + 三输入判定"的真实数据，只有自用跑量才能拿到。

**推荐路径**：自用优先 → 随加盟扩张强制使用，成为加盟体系的**事实标准**（从成本中心变成管控抓手）→ 待数据沉淀后，再把**判定引擎 / 设备适配层 / 脱敏案例库**三个模块包装为"行业版"**选择性输出**，而非整套系统对外售卖。

> 一句话差异化定位：**竞品管"收钱核销"，慢病平台管"随访"，我们管"疗效承诺的兑现与稽核"。**

**核实说明**：博卡/有赞的疗程核销与连锁权限能力来自公开行业研究转载；道生医疗功能边界、智云依从性计算细节未获确认，矩阵中标 ⚠️ 待核实；市场数据第 2 条为二手报告转载，建议后续采购原始报告核实。价格口径差异大，签约前必须询价确认。
