| 泳道角色 | 职责边界（文档原文归纳） |

| 门店 / 客服 | 服务入口、客户接待、退款受理（客户主动退款入口） |

## 二、主链路（9 环节闭环）

**核心逻辑：禁忌排查 → 评估 → 出方案 → 审核 → 签协议 → 调理 → 再评估，闭环运转**

1. **入口筛查**：禁忌症排查 = 服务入口**硬门禁**，嵌在《知情同意书》内，位置在"个人基本信息之前"；有禁忌 → 不进入服务流程。
2. **建档与评估**：调理师签署《知情同意书》（含禁忌排查 + 个人信息授权 + 询问手环佩戴意愿）→ 客户建档（个人基本信息 + 健康史）→ 经络师做**基线评估**（身体不适表现类优先，年龄段量表兜底）→ **核心健康问题诊断**（症状 / 体征 / 指标分析）。
3. **方案与审核**：经络师出具方案（治疗方案 + 生活方式干预建议）→ 方案审核（完整性 · 有效性 · 可行性）→ 审核通过后**调理设备参数一键自动下发**（明确"不新增角色"）。
4. **协议与确认**：首次出方案后签署《调理协议书》（含**无效退款条款**）→ 客户点操作确认方案 → **未签不得操作**（干预强制前置）。
5. **调理执行**：调理师按方案持续服务。
   - **生活方式干预闭环**：客户小程序每日填报（选择题记录）+ 手环自动采集睡眠/运动 + **调理师到店间隙核对**执行记录；数据留存供周期评估与退款判定使用。
   - 数据定位：手环/小程序数据是**退款判定依据**，也作为生活干预手段。
6. **周期评估**：**每 7 次服务触发一次**；判定输入 = 核心指标（为主）+ 依从性 + 手环/小程序数据；**一个调理周期 = 15~45 次**。
7. **效果判定（退款门禁）**：
   - 稳定 / 改善 → 维持原方案 · 下一周期
   - 依从不足 → 强化生活方式干预与追踪
   - **依从达标但无效** → 系统自动提醒经络师**重定全新方案**（设备：秦皇岛 → 杠2设备；其他门店 → 现有设备）
   - 高危 / 新发 / 同病 → **全面评估** → 新方案出具 → 方案调整（用药 · 饮食 · 运动）
   - **任何方案调整必回炉审核 + 客户重签**（新方案审核 + 重新签署确认）
8. **退款门禁**：
   - 客户可**随时主动**提出退款 → 先"原因分析 → 针对性挽留" → 挽留失败 · 终止退款
   - **首周期（7 次）后主动评估**：效果 + 依从性不达标 → **不经挽留，主动终止并退款**
   - 每次评估后检查退款意向；退款终止与正常结案**均须归档**，**退款原因必须记录**
9. **收尾**：全周期完成（15~45 次内完成）→ 出具**《调理效果确认》**（档案）→ 趋势归因 + 客户签字 · 可脱敏沉淀 → **归档结案**（按既定流程）。

## 三、两份文书（法律/合规基石）

| 文书 | 签署时点 | 关键内容 |
|---|---|---|
| **《知情同意书》** | 建档环节（入口第一步） | 含**禁忌症排查** + **个人信息授权**；在个人基本信息之前；同时询问手环佩戴意愿 |
| **《调理协议书》** | 首次出方案后 | 含**无效退款条款**；为**干预强制前置**条件（未签不得操作） |

## 五、文档中隐含的产品化机会点（待各成员验证，勿直接采信）

- 全链路**无系统承载**：禁忌门禁靠人、审核靠人、设备参数下发靠人，风控不可审计。
- **退款争议**风险高：退款是核心商业承诺（无效退款），但判定依赖"核心指标 + 依从性 + 手环/小程序"三类异构数据，缺少统一数据底座与判定引擎。
- **合规**：个人信息授权、健康史属敏感个人信息，需符合《个人信息保护法》健康医疗数据合规要求。
- **多角色协同**：调理师（执行）与经络师（评估/审核）职责分离，天然需要**权限隔离 + 审核留痕**。
- **设备差异**：秦皇岛门店与其他门店设备型号不同（杠2 vs 现有），参数下发需门店级设备台账。
- **量化口径**：每 7 次评估、15~45 次/周期、首周期 7 次，均是刚性业务规则，必须可配置。

## 七、⚠️ 交付形态硬约束（用户中途补充，优先级最高）

> **本产品是多门店 SaaS 系统**（不是单店自用工具）。

由此派生的架构要求：

| 维度 | 要求 |
|---|---|
| 租户模型 | `tenant`（连锁品牌）→ `region`（区域）→ `store`（门店，含直营/加盟属性）三级 |
| 数据隔离 | 全部业务数据带 `tenant_id`，**存储层隔离**，不允许仅靠应用层过滤 |
| 权限分层 | 总部 / 区域 / 门店 / 加盟商 四类可见范围；**稽核类指标对门店与加盟商不可见** |
| 政策集中 | 依从性阈值、效果判定分支、退款门禁规则、禁忌清单、周期节奏 = 总部唯一可改，门店只读，变更留痕且不回溯 |
| 运营放权 | 排班、提醒频次、本地设备参数微调、员工考核权重 = 可下放 |
| 设备台账 | 设备型号注册在**门店档案**（秦皇岛→杠2 / 其他→现有），方案只声明意图参数，系统做映射 |
| 跨店通兑 | 客户归属品牌；`owner_store`（首签店）与 `serving_store`（服务店）分离；**转店必须走系统工单** |
| 经验沉淀 | 脱敏案例库 + 标准方案模板库全连锁复用 |
| 反博弈 | 加盟门店天然有"劝客户别退"的动机 → 必须有稽核与自动升级机制，不能靠自觉 |
