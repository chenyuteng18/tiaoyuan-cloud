## TL;DR（4 行）

1. **A3 的失真方向取决于分母来源，且两个方向都真实存在**：分母取「设备台账（应戴天）」→ A3 **被低估**（设备问题罚客户）；分母取「数据存在性」→ A3 **恒为 1.0**（静默虚高）。**必须先钉死分母来源，否则 A3 的两个方向都不能用。**
2. **失真传导到判定是量化的、且命中"临界客户"**：`ΔAS = 0.286 × ΔA3`。**真实全部达标（A1=A3=A4=1.0）的客户，只要数据观测率 < 30.1% 就会被判"依从不足"**；真实合规 0.90 的客户，观测率 < 61.1% 即翻车。**最先被误判的恰是"真实达标但裕度小"的临界客户。**
3. **ECC 存在一条新传导链（须与 legacy 问题区分）**：A3 失真 → AS 跌穿 0.8 → 疗程从「稳定/改善」降为「依从不足」→ **出 ECC 分子**。这是**"伪低估"（罚自己）**；而"静默失效分母"口径则造成**"伪高估"（粉饰）**。**两种口径偏差的 ECC 影响方向相反**，不可混谈。
4. **阈值立场（明确）**：**0.8 与四维权重数值保持不动，但必须在上线前先修 A3 口径**——**口径先行、数值后校**。理由：在脏口径上跑出的 30 天基线，校准出的是**错的阈值**。

## 一、A3 失真对 AS 与判定结论的影响路径

### 1.1 口径链（先画出链路）

```
设备/App 侧                    我方系统                        判定
────────────────────────────────────────────────────────────────────────
GTL1 采集  ──BLE──▶  同步日志 / 数据落库  ──▶  A3 = 有效佩戴天 / 应戴天
   │                      │                          │
   │ 后台被杀              │ 未同步/断连              │ ×0.286（AS_refund）
   │ 未佩戴                │ 缺失无法区分             ▼
   │ 充电(5-7天续航)        └──────────────▶  AS_refund = 0.571·A1 + 0.286·A3 + 0.143·A4
   │                                                    │
   │                                                    ▼
   └──────────────────────────────▶  门槛判定：AS ≥ 0.8 ?
                                              │
                              ┌───────────────┴───────────────┐
                        AS ≥ 0.8                        AS < 0.8
                     「稳定·改善 → 维持」            「依从不足 → 强化干预」
                              │                              │
                              ▼                              ▼
                       进 ECC 分子                  **不进 ECC 分子**
```

### 1.2 量化模型

定义：
- `T` = 应戴天（分母）｜`N_true` = 真实有效佩戴天｜`N_obs` = 系统**观测到**的有效佩戴天
- **数据观测率** `f = N_obs / N_true`（`f ≤ 1`；后台被杀、断连、未同步都降低 `f`）
- `A3_true = N_true / T`，`A3_obs = N_obs / T = f × A3_true`

**核心传导公式**：

```
AS_refund = 0.571·A1 + 0.286·A3 + 0.143·A4

∂AS / ∂A3 = 0.286        ← A3 每损失 0.10，AS 下降 0.0286
ΔAS = 0.286 × (A3_true − A3_obs) = 0.286 × A3_true × (1 − f)
```

**每损失 10% 观测率（A3_true = 1 时），AS 下降 0.0286**；损失 70% → AS 下降 **0.20**（足以击穿门槛）。

### 1.3 翻车临界线（break-even，可复算）

设客户各维真实合规水平一致为 `c`（`A1 = A4 = A3_true = c`），则 `AS_true = c`：

```
AS_obs = c·(0.714 + 0.286·f)
AS_obs = 0.8  ⟹  f* = (0.8/c − 0.714) / 0.286
```

| 真实合规 `c`（A1=A3=A4） | AS_true | **翻车临界观测率 f\*** | 含义 |
|---|---|---|---|
| 1.00 | 1.000 | **30.1%** | 全达标客户，观测率跌破 30% 即被判"依从不足" |
| 0.95 | 0.950 | 44.8% | 裕度 0.15，仍易翻车 |
| **0.90** | 0.900 | **61.1%** | **观测率跌破 61% 即翻车** |
| 0.85 | 0.850 | 79.4% | 观测率跌破 79% 即翻车 |
| 0.83 | 0.830 | 87.4% | 裕度仅 0.03 |
| **0.81** | 0.810 | **95.7%** | **几乎任何数据损失都会翻车** |
| 0.80 | 0.800 | 100% | 真实恰好达标者，**只要有任何数据损失即翻车** |

> ⚠️ **两个反直觉结论**（必须写进设计）：
> 1. **最危险的不是"完全不戴"的客户，而是"真实达标但裕度小（0.80~0.85）"的临界客户** —— 他们的真实结论应是「维持原方案」，却因数据损失被推入「强化干预」。**误判方向单一（真达标 → 误判不足）**，属于**系统性惩罚**。
> 2. **全达标客户（c=1.0）也只有在观测率极低（<30.1%）时才翻车** —— 这解释了为什么"上了线才发现"：**数据损失是渐进的、静默的，指标在 30%~70% 损失区间内看起来"只是偏低"，不会报错。**

### 1.4 完整算例（可复算）

客户 C：真实 `A1 = 0.90`、`A3_true = 0.90`、`A4 = 0.90`（真实各维一致）。因 GTL1 App 被国产 ROM 杀后台 + 每周约 1 天充电，`f = 0.50`。

| 项 | 计算 | 值 |
|---|---|---|
| `A3_obs` | 0.50 × 0.90 | **0.450** |
| `AS_true` | 0.571×0.9 + 0.286×0.9 + 0.143×0.9 | **0.900** ≥ 0.8 → **应判「稳定·改善→维持」** |
| `AS_obs` | 0.571×0.9 + 0.286×0.45 + 0.143×0.9 = 0.5139 + 0.1287 + 0.1287 | **0.771** < 0.8 → **被判「依从不足」** |
| **判定反转幅度** | 0.900 − 0.771 | **0.129** |

**结论**：**同一客户、同一真实行为，仅因"设备数据没传上来"，判定从"维持原方案"翻转为"依从不足 + 强化干预"。** 而"强化干预"意味着：系统推送提醒、追加生活方式任务、门店侧记为依从问题 → 客户体验受损，且该疗程**不进 ECC 分子**（见 §3）。

> ⚠️ **口径 ≠ 数据（团队规则③，双向执行）**：
> - 本文**不是**在说"佩戴率不重要"；（A3 是 AS 的一个真实维度）
> - 也**不是**在说"风险不存在"；（风险已被量化到具体阈值）
> - 而是在说：**当前没有任何可支撑 A3 的可信数据，且口径未定时，两个方向的偏差都不可控。→ 结论是"必须先定口径"，不是"可以先用着"。**

### 1.5 重归一化的具体条件（**A3 何时应判 `applicable=False` 而非记 0**）

**总原则**：**A3 的缺失只有在"客户可控制且可观测"时才记 0 分**；凡属"设备/数据源/链路层面不可得"，一律 `applicable=False`、**权重重归一、不计扣分**。这与 AS v2 既有的「结构性缺失 vs 行为性缺失」分流**同构**，只是把"结构性"的定义从"未同意佩戴"**扩展到"设备不可得"**。

| 条件编号 | 触发条件 | A3 处置 | 依据 |
|---|---|---|---|
| **G0** | 未同意佩戴（既有条件） | `applicable=False`，权重重归一 | PRD P0-02 / AS v2 既有 |
| **G1** | **SDK 无佩戴检测字段 → 无法区分"未佩戴"与"佩戴但无有效读数"**（任务 #2 §3.2） | **`applicable=False`（整维不可用）** | 区分不了 → 分子不可信 → **不得用不可信分子罚客户** |
| **G2** | 缺数据当天**无"无记录"标记**（静默不返回，任务 #2 §4.1） | `applicable=False` | 系统"看不见缺失"→ 分母不可信 |
| **G3** | **我方同步日志显示"尝试同步但失败"**（链路侧故障，非客户行为） | 该段缺失天**排除出分子**（视同不可得），或整周期 `样本不足` | 责任在我方/厂商，不在客户 |
| **G4** | 厂商侧**服务/接口故障公告**期间 | 该期间缺失天**排除** | 同上 |
| **G5** | **设备硬件故障 / 已报修 / 已换机** | 该段 `applicable=False` | 设备台账状态可查（见 §1.6） |
| **G6** | 应戴天 < 7（**既有护栏**） | AS 标 `样本不足`，**不得用于退款门禁** | PRD §5.3 既有护栏 |
| **G7** | **技术性缺失**（瑞思 M1/M8：安卓杀进程、iOS 系统蓝牙自动回连）——判据：**有前置有效佩戴记录 + 无 `device_unbind` 事件 + 断点突变** | `applicable=False`（并入结构性处理） | **§1.7 与瑞思对齐**；识别依赖 `device_unbind`（**可靠**），**不依赖 `app_uninstall`** |
| **G8** | **合规摘除**（瑞思 M4：住院 / 洗浴 / 桑拿按说明书摘下）——判据：有 `pause_period` 申报 | **暂停期从"应戴天"分母中剔除** + `applicable=False` | **§1.7**；依据强度最高（**厂商自己要求客户摘下**，判成不依从无法辩护） |

> ⚠️ **G7/G8 的归属说明（与瑞思订正一致）**：我原 §1.5 的条件以"设备/链路层面不可得"为轴；瑞思补充的 M1/M8/M4 是**同一根轴上的具体成因**，故并入 G 系列（G7 技术性、G8 合规摘除），**处置一律指向"不扣分"**。**两处口径必须一致：任务 #2 §3.4 D0 与任务 #3 §1.5 G 系列均指向 `applicable=False`，无冲突。**
> ✅ **三形态通用性（瑞思 2026-09-18 对表确认）**：**G7 判据结构不随接入形态改变**（成因从"厂商 App 被杀"变为"我方 App 被杀"，判据仍为 `前置有效记录 ∧ 无 device_unbind ∧ 断点突变`）→ **G7 三形态通用，无需分形态**。详见 §1.8①。

**重归一化的数学**（沿用 AS v2 公式 `AS = Σ(wᵢ·sᵢ) / Σ(wᵢ)`，仅对 `applicable=True` 求和）：

- **仅 A3 不可用**（G1/G2/G5）：AS_refund 剩余权重 A1 0.571 + A4 0.143 = **0.714** → 重归一 → **A1 = 0.800、A4 = 0.200**（0.800 + 0.200 = 1.000 ✓）
- **A3 + A2 均不可用**（AI 上端未上、手环不可得）：仅剩 A1 与 A4，同上 → **A1 0.800 / A4 0.200**
- **只有 A1 可用**：AS_refund = A1（权重 1.0）

> ⚠️ **关键推论（结构性后果，须业务知悉）**：**若 A3 在 Phase 0 实际整体不可得（G1/G2 触发），AS_refund 会退化为 `0.80×A1 + 0.20×A4` —— 手环维度实质性退出判定链。** 这**与 PRD 既定的"手环自愿、依从底线由到店履约 + 门店代核兜底"是同一条设计精神**（上游汇编 A4-③、PRD 反直觉洞察②），**方向正确、不是失控**；但必须**显式记录为"降级态"并留痕**，不得让"A3 退出"静默发生（否则日后无人知道 A3 从未生效）。

### 1.6 分母口径的抉择（**决定偏差方向，最高优先级**）

| 分母来源 | 定义 | 偏差方向 | 判定 |
|---|---|---|---|
| **台账分母**（推荐） | `应戴天` = 设备台账 `绑定日 → 解绑日` 的**日历天数** | **低估 A3**（设备问题罚客户）→ 需 §1.5 重归一兜底 | ✅ **采用**（分母不可被数据清洗） |
| **数据存在性分母** | `应戴天` = **有数据的天数** | **A3 恒 = 1.0**（静默虚高，无告警） | ❌ **禁止** |
| **权威分母（混合）** | 台账分母 + G3/G5 排除段 | 方向可控 | ✅ **采用（终态）** |

**为什么必须台账分母**：与我在《集成指标规格》§11.1 / §11.2 坚持的「**缺失不得被平均或清洗**」原则（*既有原则；复现于本节，见「一附」*）**同源** —— 原文口径为"**分母不能被稀释或清洗来讨好指标**"。数据存在性分母 = **用"我没采到"当"客户没戴"来定义分母** → 指标可被粉饰。**唯一解法 = 分母来自台账（我方可控），不来自数据（设备可控）。**

### 1.7 与瑞思（用户研究员）的口径对齐（2026-09-18 收其订正后）

瑞思从其用户侧给出 **8 个"会被误判为行为性缺失"的场景（M1–M8）**（见 `gtl1-adherence-ux-2026-09-18.md` §四）。**其结论与我的 G 系列处置一致**（技术性缺失应不扣分、合规摘除应不扣分），但在**"用什么信号识别"**上有一次重要订正，须在此同步：

| 信号字段 | 可获取性 | 我方处置 |
|---|---|---|
| **`device_unbind`**（客户在 App 内点"解绑设备"） | ✅ **可靠**（App 内动作，可正常上报） | **列为硬需求**（M6 扩展） |
| **`unbind_reason`** | ✅ 可靠（同上） | 硬需求 |
| **`charge_reminder_sent_at`** | ✅ 可靠（我方/厂商推送记录） | 硬需求（支持瑞思 M3/M6 "首次免责、提示后仍不充才追责"） |
| **`app_uninstall`** | ❌ **不可靠** —— **App 无法上报自身被卸载**（同"崩溃上报无法上报自身缺失"）；卸载只能靠厂商推送通道的**卸载回执 / 重装检测**，**能否拿到取决于厂商，属未确认** | **降级为"待厂商确认"，不得当作已成立能力记账** |

**判据随之收窄（不影响实质结论，只改判定信号）**：

```
「技术性缺失（G7）」判据：
  有前置有效佩戴记录  AND  无 device_unbind 事件  AND  断点突变
  （原写法含"无 app_uninstall" → 因 app_uninstall 不可靠，删去该条件）
```

> ⚠️ **关键澄清**：**"客户主动放弃"的唯一可靠信号 = 有没有一次主动解绑动作（`device_unbind`）**。这条**不依赖厂商开放即可成立**，对我的口径**完全够用**。因此 **G7 的识别不因 `app_uninstall` 缺失而失效**。
> ⚠️ **与反博弈的关系**（瑞思 §4.3-4）：若把技术性缺失并入"不扣分"，理论上存在"假装被杀以规避扣分"的空间 → **瑞思建议不为此收紧**（A3 仅 0.20 且不参与效果主判据，为它增博弈复杂度不划算），**用 `device_unbind` 留痕替代审批** —— **我同意此判断**（符合"证据不足时既不罚客户也不奖自己"的双面原则）。

**不依赖新增字段的兜底（我采纳，建议写入 A3 执行说明）**：评估页在既有"手环缺失 N 天 / 覆盖率"字段旁标注「**缺失原因待门店确认**」，由调理师在**既有到店接触点**问一句并选结构化原因 → **把"不可观测"转成"可询问"**。这是在缺 `app_uninstall` 时，**把 G7（杀进程类）与"主动放弃"分开的现实手段**，**成本落在已存在的触点，0 新增字段**。

### 1.8 三接入形态对 G 系列与字段可得性的影响（2026-09-18 与瑞思对表）

> 🔴 **本条最重要、决定业务方如何选形态（置顶，勿在读文末时才看到）**：
> **形态选择同时决定两件方向相反的事 —— 形态③（健康平台中转）对「数据可得性」是利空（加重 A3 不可观测）；形态①（SDK 直连、我方原生 App）对「字段可得性」是利好。**
> ⚠️ **但形态①的利好是有前提的**：它要求**变更"客户 = 微信小程序"这一载体裁定**（新增原生 App）—— **业务成本远大于字段收益**。故**不得只看到"形态①利好字段"就去选形态①**，须把"载体变更成本"与"字段收益"一并称量。

瑞思已把我在任务 #2 §2.0 的「SDK 宿主 = 原生 App → 无法嵌微信小程序」落进其文件的「§一附：三形态链路分叉」。**三处对我口径轴的影响，逐条确认如下：**

**① G7「技术性缺失」三形态通用，判据结构不随形态改变** ✅

| 形态 | 技术性缺失的主要成因 | G7 判据 |
|---|---|---|
| 形态①（SDK 直连，**我方**原生 App） | **我方 App 被杀**（安卓 ROM）/ iOS 系统蓝牙自动回连 | **不变**：有前置有效记录 ∧ 无 `device_unbind` ∧ 断点突变 |
| 形态②（厂商云 API） | 厂商 App 被杀 / 厂商同步失败 | 同上 |
| 形态③（健康平台中转） | 平台同步延迟 / 客户未主动打开厂商 App 触发写入 | 同上 |

> **结论**：**成因从"厂商 App 被杀"变为"我方 App 被杀"，但判据结构完全不变 → G7 三形态通用，无需分形态。**

**② 场景描述的形态注（M1/M8 须加）** ⚠️ —— **Android 阻断层归属未定，须实测，不得推测**

- **iOS：确定成立** —— 手册明写苹果"系统蓝牙默认连回该设备，需忽略 App 才能检测到"；**系统级自动回连是 OS 行为，我方 App 绕不过** → 形态①下 iOS 客户仍会撞 S6 陷阱 → **M8 成立**。
- **Android：手册未说明阻断层归属**（手环/US 系统蓝牙层 vs 厂商 App 实现层）→ **须实测**（瑞思已挂 **实验 B-2**：用第三方 BLE 工具连已被系统蓝牙占用的 GTL1）。**这是"手册没写的部分不许推测"的诚实标注** —— 故 **M1（安卓杀进程）** 的场景描述须加注：「**成因随形态改变；安卓蓝牙阻断层归属待实验 B-2 定性**」。
- **→ 对我的影响**：**仅场景描述加形态注，G7 判据与处置均不变。**

**③ 形态③（健康平台中转）会加重 M2/M5 类 → "结构性不可观测"占比须按形态单列** 🔴

- 机理：健康平台中转**必然丢实时性**（同步有延迟、且依赖客户**主动打开厂商 App** 触发写入健康库）→ **断连期比形态②更长**。
- **→ 后果**：§2.2 的 **M2（有效测量时长）/ M5（失败原因码）** 在形态③下**更不可得**；且**"结构性不可观测"占比在形态③下更高**。
- **⚠️ 对指标口径的要求（防平均数掩盖）**：**A3 的"结构性不可观测占比"必须按形态单列，不得三形态平均** —— 否则形态③的高占比会被形态①/②拉平，**掩盖"该形态下 A3 根本不可用"这一事实**。**此要求即「缺失不得被平均或清洗」原则（*既有原则；第三处复现，见「一附」*）**——与既有"HSI 覆盖率须按门店级 + 全网级分别告警"（指标规格 §11.2 样本护栏）**同源**：高缺失的单元不得被聚合平均掉。

**④ 利好：形态①下 `pause_period` / `device_unbind` 可得性反而更好** ✅

- 机理：**形态① 是我方自研 App 宿主** → **解绑动作与暂停期申报都在我方自己手里，不依赖厂商** → **G7/G8 的判据可执行性上升**（`device_unbind` 可靠、`pause_period` 可自建入口）。
- **⚠️ 前提（瑞思声明不越权，我亦不越权）**：**形态① 须不与"微信小程序"硬约束冲突** —— 这**取决于业务方对客户端载体的裁定**（我的任务 #2 §2.0 / 待确认项 B1）。**在载体未定前，此"利好"为条件性利好，不得当作已成立。**

> **⚠️ ③ 与 ④ 的张力（详见本节开头的置顶提示）**：**形态③ 对"数据可得性"是利空（加重不可观测）**；**形态① 对"字段可得性"是利好（但前提是变更载体裁定）**。**→ 形态选择同时决定"结构性不可观测占比"与"字段可得性"，是三形态对比中最该被业务方知悉的一条。**

## 一附、同源护栏原则『缺失不得被平均或清洗』（**既有 · 三处复现**）

> **命名（主理人裁决 2026-09-18，受限采纳）**：**「缺失不得被平均或清洗」原则（*既有原则；本次系在第三处复现，非新创*）**。
> 🛑 **禁写「本次提出的原则」** —— 该原则在《集成指标规格》§11 已存在、HSI 处已应用；若以"本次提出"口吻命名，会造成两个后果：① 让人误以为指标规格原先没有这条、**凭空多出一项待评审增项**；② 后续回查指标规格 §11 会发现"原文没有这个名字"，**反而质疑文档可信度**。→ **凡引用处，一律写「既有原则，复现于 X 处」。**

### 三处出处（同一原则的独立复现）

| 处 | 出处 | 该处形态 | 原文口径 |
|---|---|---|---|
| ① | 数析《集成指标规格》**§11.1 / §11.2**（ECC 计入裁定） | **原始出处** | 「分母不能被稀释或清洗来讨好指标」；`migratable=false` → 计入分母、不计入分子 |
| ② | 数析《集成指标规格》**§11.2 / §11.2.1**（HSI 可判定覆盖率） | 第二次应用 | **门店级 <20 标"样本不足"、但全网/租户级仍须按总体告警**（防"每家店都 <20 则全网塌方却无人告警"） |
| ③ | **本文 §1.8③**（A3 不可观测占比 + 任务 #2 §2.4） | **第三次复现** | **A3 的"结构性不可观测占比"须按接入形态单列，不得三形态平均**（防形态③高占比被形态①/②拉平、掩盖"A3 在该形态根本不可用"） |

**一句话定性（主理人要求）**：**这条原则是"防止指标被粉饰"的护栏，不是"数据不得清洗"的禁令。**

### 两条限定（本裁决的实质内容，非附注）

**限定 1 · 命名须写明"既有原则的复现"，不得写成"本次新创"** —— 见上方命名与 🛑 警示。

**限定 2 · 适用范围必须收窄，只约束两件事，不得泛化为"任何分母都不得清洗"**：

✅ **该原则只约束**：
1. **因缺失而剔出分母**（把没数据的单元悄悄扔掉 → 分母虚小）；
2. **跨单元聚合平均**（把高缺失单元与低缺失单元平均 → 缺口被掩盖）。

🚫 **它不约束、也不得被援引来反对**：
1. **重复记录去重**（同一 `device_id` + 同一时间戳的重复上报）；
2. **测试数据 / 联调数据剔除**（`is_test` 标记行）；
3. **异常值技术性修正**（越界时间戳、明显错误单位）。

> ⚠️ **为何必须写这条边界**：若该原则被泛化为"分母一律不得动"，研发做数据清洗时会**无据可依** —— **去重与剔测试数据是正当且必要的**，被这条原则误挡会直接导致指标数值错误（**重复计数**）。**"缺数据不能说"与"假数据要清掉"是两回事。**

## 二、「不补 0」原则的技术前提 → 最小字段清单

### 2.1 静默失效的机理（复述 + 与 A3 的连接）

PRD P0-10 要求「同步失败或未佩戴 → 标记空缺，**不得自动补 0**」。**前提是系统"知道"这一天应有数据但缺失**。若 SDK 只给日汇总、缺数据当天不产生记录：

```
真实：应戴 7 天，实戴 5 天（1 天充电 + 1 天蓝牙未同步）
SDK 返回：5 条日记录
系统解析：5 天 = 全部记录
A3 = 5 / 5 = 1.000    ← 分母从 7 变成 5
```

- **字面层**：没有补 0 → P0-10 字面"遵守"。
- **语义层**：缺失天**不进分母** → **等于把分母扔掉了** → A3 **虚高**（与 §1.3 的低估**方向相反**）。
- **静默性**：无报错、无告警、无"缺失 N 天"标记 → **P0-10 第 4 条验收（评估页显式暴露缺口天数）一并失效**（无数据可暴露）。

> **两个方向并存的风险**：同一套数据，若分母取**台账** → A3 低估（§1）；若分母取**数据存在性** → A3 虚高（§2）。**这正是"分母来源必须先钉死"（§1.6）的原因——分母来源一换，偏差方向就反转。**

### 2.2 最小字段清单（**向厂商提问的硬输入**）

**M1–M7 为"最小充分集"，缺任一则静默失效不可根除**（沿用任务 #2 §4.3，此处标注其用途与缺失后果）：

| # | 最小字段 | 用途 | 缺它的后果 |
|---|---|---|---|
| **M1** | **佩戴状态**（`wear` / `off_wrist` / `unknown`，逐日或逐时间片） | 区分"未佩戴"与"佩戴" | §1.5 G1 无法解除 → A3 整维不可用 |
| **M2** | **有效测量时长**（分钟/天）或有效采样点数 | 定义"有效佩戴"分子的下限 | 无法判断"戴了但没采到"。⚠️ **形态③下更不可得**（平台侧通常只给聚合值，见 §1.8③） |
| **M3** | **数据覆盖区间**（每条记录起止时间戳） | 判断"部分覆盖"的天 | 只能得"有/无"，无法得"覆盖多少" |
| **M4** | **记录存在性语义**：无数据时返回「无记录」标记 vs 静默不返回 | **"不补 0"是否成立的关键** | 静默不返回 → §2.1 必然发生 |
| **M5** | **同步/采集失败原因码**（未佩戴/未同步/蓝牙断/电量低/传感器失败） | 缺口归因 | 缺口只能记"原因未知"，G3 无法触发。⚠️ **形态③下更不可得**（平台中转无原因码，见 §1.8③） |
| **M6** | **设备绑定状态 + 设备唯一 ID** + **`device_unbind`（解绑事件）+ `unbind_reason`**（含绑定/解绑时间戳） | **产生台账分母**（§1.6）+ 区分"主动放弃"与"技术性缺失"（§1.7 G7） | 分母无法由台账产生 → 退回"数据存在性分母"（禁止）；无法区分主动放弃 |
| **M7** | **电量 / 充电状态** + **`charge_reminder_sent_at`**（充电提醒发送时间） | 识别"充电期缺口"（5–7 天续航 ≈ 每周 1 天）+ 支持"首次免责、提示后仍不充才追责" | 把充电误判为"未佩戴"（误罚客户） |

> **两档处理（与瑞思订正一致）**：
> - ✅ **可靠、建议硬需求**：`device_unbind` / `unbind_reason` / `charge_reminder_sent_at`（**+ 上述 M1–M7 中厂商侧能力项**）
> - ⚠️ **降级为"待厂商确认，不得当作已成立能力"**：`app_uninstall`（**App 无法上报自身被卸载**，只能靠厂商推送通道的卸载回执 / 重装检测）
> - **台账分母的实现不依赖 `app_uninstall`** —— 只用绑定/解绑时间戳（`device_unbind` 可靠），故 **§1.6 的台账分母方案成立性不受此订正影响。**

### 2.3 若拿不到 M1–M7：A3 的改口径方案（按优先级）

| 方案 | A3 处置 | 标注 |
|---|---|---|
| **D0（首选）** | **A3 `applicable=False`，权重重归一，不扣分** | **降级口径，需研发评审**；最保守、最合规 |
| **D1** | 改名 **「手环数据覆盖率」** = 有数据天 / 台账应戴天，**仅进 `AS_ops`，不进 `AS_refund`** | **不得称"有效佩戴率"**（名实不符会误导） |
| **D2** | 以「有效测量时长 ≥ 阈值（如 ≥10h/天）」定义"有效佩戴天"（需 M2） | 需校准阈值 |
| **D3** | 用**我方同步尝试日志**反推（"同步过"代理"戴过"） | **仅能证"同步过"、不能证"戴过"**；代理口径，须显著标注 |
| **D4** | 保留 **人工降级 + 留痕**（调理师到店代核） | PRD 已有此思路；**人工口径不进退款门禁** |

**护栏复用**：无论采用哪个降级口径，均沿用 **G6（应戴天 <7 → 样本不足）** 与**覆盖率不足自动降权**（PRD §5.3）。

## 三、对 ECC 与 HSI 的传导检查

> 任务问：手环换厂商是否会污染 ECC / HSI 的**任何一环**？答：**HSI 第 1 项的 legacy 传导链仍不成立（不变）；但存在一条"非 legacy"的新传导链，经 AS 门槛进入 ECC 分子。** 逐项检查如下。

### 3.1 ECC 传导检查

`ECC = Σ 疗程([已结案] × [效果 ∈ {稳定,改善}] × [退款=否])`

| 环节 | 是否受手环影响 | 机理 |
|---|---|---|
| ECC **分母**（结案疗程数） | ❌ **不受** | 手环数据与"是否结案"无关 |
| ECC **分子 - 效果项** `[效果∈{稳定,改善}]` | ✅ **受（经门槛）** | 判定链：`有效 = 核心指标改善/稳定 **且 AS ≥ 0.8**`。B6 规则表明确："AS < 0.8 → 依从不足"（**优先于效果分支**）→ **效果达标但 AS<0.8 的疗程不进分子** |
| ECC **分子 - 退款项** `[退款=否]` | ⚠️ **间接（推断）** | 依从不足路径是"强化干预"不直接退款；但误判可能损害体验 → 退款率上升（**推断，非本店数据**） |

**传导链（成文，防重复提起）**：

```
A3 失真 → AS_refund 跌穿 0.8 → 疗程判「依从不足」
        → 不满足 [效果∈{稳定,改善}]（依从门槛未过）
        → 出 ECC 分子 → ECC 低估（"伪低估"，罚自己）
```

**两个方向的 ECC 影响（不可混谈）**：

| 偏差模式 | A3 | AS | ECC 分子 | ECC 值 | 性质 |
|---|---|---|---|---|---|
| **台账分母 + 数据损失**（§1） | 低估 | 低估 | 达标疗程被误排除 | **低估** | **罚自己**（保守，非粉饰） |
| **数据存在性分母**（§2） | 恒 1.0 | 虚高 | 不达标疗程被误纳入 | **虚高** | **粉饰**（危险） |

> ⚠️ **与 §11.1「不剔除」原则的关系（重要澄清）**：ECC 分子减少**不违反**「**缺失不得被平均或清洗**」原则（*既有原则，见「一附」*）——因为**减少的是分子，且方向是保守的**。但**必须止于 ECC**：**不得让 A3 失真影响"可判定覆盖率"的分母**（覆盖率分母仍按 `migratable` / 基线时点定义，与手环无关）。

### 3.2 HSI 8 项传导检查（逐项）

| # | HSI 项 | 受手环影响 | 理由 |
|---|---|---|---|
| 1 | ECC（绝对量 + 环比） | ✅ **受（经 §3.1 传导链）**；**但 legacy 传导链不成立（不变）** | 绝对量随分子变化；**"ECC→HSI→门店排名"的 legacy 传导链仍是"不成立"**（legacy 不进 Σ）——**这是两回事，须分开记** |
| 2 | 退款率 | ⚠️ **间接（推断）** | 依从不足不直接退款；误判→体验→退款（**推断**） |
| 3 | 效果类退款触发率 | ⚠️ **间接（推断）** | 同上 |
| 4 | 协议签署合规率 | ❌ **不受** | 与手环无关 |
| 5 | 方案一次审核通过率 | ❌ **不受** | 与手环无关 |
| 6 | 小程序每日填报率 | ❌ **不受** | 手环 ≠ 小程序填报（不同维度） |
| 7 | 稽核问题数 | ⚠️ **间接（推断）** | 若"手环缺项"被误记为稽核问题 → 上升；**应为"警告不阻断"**（PRD #36/ARC-08） |
| 8 | 可判定覆盖率 | ❌ **不受**（**须护栏**） | 覆盖率分母按 `migratable`/基线时点定义，**与手环无关**；**必须防止有人把"手环缺失天"算进覆盖率分母** |

**HSI 使用约束（回填既有 4 条，增补第 5 条）**：

> **5（新增）**：**HSI 第 1 项 ECC 若因 A3 失真而下降，须与"真实依从恶化"可区分** —— 建议在 ECC 卡片并列展示 **A3 数据可用性状态**（`A3_applicable` + 观测率 `f`），避免把"设备问题"读成"门店经营问题"。**否则门店会被系统性误排名。**

### 3.3 传导检查总结（一句话）

**手环换厂商 → 不污染 ECC 分母、不污染 HSI 第 4/5/6/8 项、不污染 legacy 传导链；但会经 AS 门槛污染 ECC 分子与 HSI 第 1 项，并可能经"误判体验"间接影响第 2/3/7 项。** 故**不能写"不传导、无需改"**；正确结论是**"传导存在、路径明确、可通过 §1.5 重归一化条件 + §1.6 台账分母封堵"**。

## 四、阈值是否需要重校准（**明确立场**）

### 4.1 三个数字的现状

| 数字 | 现值 | 标注 |
|---|---|---|
| AS 门槛 | **0.80** | 建议值，需真实数据校准 |
| 四维权重 | **0.40 / 0.30 / 0.20 / 0.10** | 建议值，需真实数据校准 |
| AS_refund 重归一 | **0.571 / 0.286 / 0.143** | 建议值，需真实数据校准 |

### 4.2 数析立场：**数值保持不动，但必须先修口径（"口径先行、数值后校"）**

**明确回答"上线前调整 vs 保持不动等 30 天基线"：→ 保持数值不动，等待 30 天基线后再校准；但"等"的前提是"先修口径"，二者有严格先后。**

**三条理由（不接受"待校准"作为交付）**：

| # | 理由 | 说明 |
|---|---|---|
| **1** | **在脏口径上校准 = 用噪声拟合噪声** | 若 A3 口径未修（分子缺失、分母来源未定），跑出的 30 天基线**本身就是失真的** → 用它校准阈值，得到的是**"能拟合失真数据的阈值"** → **错得更牢**。故**必须"先修口径，再采基线，最后校准数值"** |
| **2** | **偏差来自分子缺失，不是阈值高低** | §1.3 的翻车是**结构性偏差**（分母不变、分子偏低）→ **调低阈值只能掩盖、不能解决**；调低 0.8 会让所有真实依从不足的客户被误判为达标（**反向误判，更危险**） |
| **3** | **已有正确解：加口径护栏 ≠ 动数值** | 正解是 **§1.5 重归一化条件（G0–G8）+ §1.6 台账分母**，它们**在不改任何数值的前提下消除偏差**。**改数值是错的方向**（且会破坏与《集成指标规格》§4.3 已冻结的 AS v2.1 一致性） |

### 4.3 上线前**必须**完成的（"保持不动"的前置条件，不可省）

| # | 前置项 | 责任方 | 不做的后果 |
|---|---|---|---|
| **P-1** | **钉死 A3 分母来源 = 设备台账**（§1.6） | 研发 / 数析 | 偏差方向不可控（低估/虚高都可能） |
| **P-2** | **落实 §1.5 重归一化条件 G0–G8**（尤其 G1/G2：SDK 无佩戴检测 → A3 `applicable=False`；G7/G8：技术性缺失 / 合规摘除同样不扣分） | 研发 / 数析 | 临界客户被系统性误判"依从不足" |
| **P-3** | **A3 数据可用性状态入库**（`A3_applicable` + 观测率 `f`），评估页与 ECC 卡片可见 | 研发 | 门店被误排名；判据不可审计 |
| **P-4** | 30 天基线采集**在口径修正后**才开始 | 数析 | 基线失真 → 校准失效 |

> **一句话立场**：**"0.8 和 0.20 现在不要动——动了也白动，甚至更糟；但 A3 的口径现在必须动，否则将来连'能不能校准'都不成立。"**

### 4.4 校准启动条件（可执行判据）

| 条件 | 判据 |
|---|---|
| 校准**可以**启动 | P-1~P-4 全部完成 **且** 有效样本 ≥ 门槛（沿用 AS 护栏：应戴天 <7 不入样本；建议门店级样本另设护栏） |
| 校准**不得**启动 | A3 口径未修 **或** A3 数据可用性 `f` 在样本内波动过大（说明口径仍不可控） |
| 校准**输出** | 新 0.8 / 新权重的**建议值 + 置信区间 + 灵敏度分析**（沿用《集成指标规格》§1.4 MCID 的处理方式，**不得直接拍板**） |

## 五、量表侧无关性确认（**一句话**）

**确认：手环换厂商（GTL1 替代 HUAWEI Health Service Kit）不影响 0–4 量程裁决、canonical 效果词表（`effect_verdict` E1–E5）、MCID 门槛（0–16 下 ≥3 分）、AS v2.1 双模式（`AS_refund` / `AS_ops` 分离），**无需重审**** —— 理由：上述四项**全部取自 02 表自评量表（同源题组 0–4 五级）**，属**量表侧**；而手环数据**只进依从性输入（A3）、绝不进 `effect_verdict`**（PRD §5.3 手环定位收紧）。**设备厂商变更属"数据源侧"，与"量表侧"完全正交。**

> 附：**唯一需要联动的量表侧事项** = **无**。若后续有人以"换了设备"为由要求重审量程/词表/MCID，**可据此一句话驳回**。
