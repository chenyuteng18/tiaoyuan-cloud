## TL;DR（结论先行 · 6 条）

1. **补拉确实解耦了"打开频次 λ"与"观测率"** —— 把"每天必须打开"降为"**每 N 天内至少打开一次**"（N = 设备留存窗口）。这是本轮**唯一实质性突破**，**低 λ 客户获益最大**。
2. **但观测率上限 = `s`（单次前台同步成功率），不是 λ、也不是 N（保守模型）**。**要跨过 `f*` ≈ 91.5% 需 `s` > 0.915 —— 而 `s` 与 `N` 均未取证** → **不得主张"补拉必然跨过 `f*`"**。
3. **留存窗口 N 是本轮最大未知量，按数据类型差异巨大**：`bufferSize`=4000 若指**心率逐点**，N 仅 **≈3~28 天**；若指**日聚合/睡眠段**，N 可达**数月**（推定 **N ∈ [≈3 天, 数月]**）。**A3 相关 N 取决于"佩戴/有效时长"是否为独立逐日流** —— 须厂商确认。
4. **`isWear` 是双刃**：能识别脱腕（好），但其 **`(-1,255) 无效`** 值域若被当"脱腕"，会把**设备异常误判成"客户没戴"（冤枉客户）** → 无效值**一律归技术性缺失（不扣分）**，须向厂商要"设备异常原因码"。
5. **A3 口径建议**：分母 = 台账应戴天（**不清洗**）；分子 = 补拉历史天 + 当日天的**有效佩戴天**（历史天**计入分子**）。三重缺失分档：① 未同意佩戴 → 结构性 → `applicable=False`；② 同意但长期不戴 → 行为性 → 扣分；③ 设备/同步取不到 → 技术性 → 不扣分。
6. **A3 定位修正**：补拉把上限从「打开率（≈0.85）」抬到「`s`」、**并使"技术性缺失"占比下降**；但**因 N/s/A6 三项未证，A3 只能升为"条件可算"，不能升为"无条件算准"**。不满足条件时按既有规则 **整维 `applicable=False`、权重重归一**（依从性模型退化为三维 `0.80·A1 + 0.20·A4`）。

## 一、留存窗口 N 的取证与估算（**本轮最关键未知量**）

### 1.1 `bufferSize`=4000 意味着多少天？（**按数据类型分别估，推定**）

`getVersion()` 返回 `bufferSize`（示例 4000）—— **文档未写单位是"条"还是"字节"，也未写是"单类型"还是"全类型合计"** → 下列为**推定区间**。

| 若 4000 指… | 单条粒度（推定） | 日占用条数 | **N（天数）推定** |
|---|---|---|---|
| **心率逐点 · 1/5/10 min** | 1 条/分钟~10 分钟 | 1440 / 288 / 144 | **≈ 2.8 / 13.9 / 27.8 天** |
| **步数 · 小时聚合 / 睡眠段 / 运动会话** | 1 条/小时 ~1~3 段/天 | 24 / ~3 / ~1~2 | ≈167 天 / 数千天 / 2000+ 天 |
| **日聚合（若有）** | 1 条/天 | 1 | 4000 天（受策略不限容量） |

> **推定结论**：**N 区间极大（≈3 天 ~ 数月），单点不可定**。**A3 只需"当天是否有效佩戴/有效测量时长"，不需完整心率时序** → **A3 的约束性 N = "佩戴/有效时长"这一路数据的留存**，而非全局 `bufferSize`。**若 A3 判据可用"逐日佩戴/有效时长"独立流 → N 大概率 ≥ 30 天**（日记录极小）；**若只能以"心率逐点存在性"代理佩戴 → N 可能仅 ≈3~28 天**。

### 1.2 **必须向厂商确认的具体问题**（待厂商答复）

| # | 问题 | 为什么必须问 |
|---|---|---|
| **V1** | `bufferSize`=4000 的**单位**（条/字节）与**计入口径**（单一类型/全类型合计）？ | 决定 N 的基数 |
| **V2** | 逐日历史接口（心率/步数/睡眠/运动）的**单条粒度**（原始点/分钟/小时/日聚合）与**各自留存天数**？ | 决定 A3 相关 N |
| **V3** | **是否存在"逐日佩戴状态/有效测量时长"的独立留存流？留存多少天？** | **直接决定 A3 的 N** |
| **V4** | 逐日接口 `{year,month,day}` 的**可查询回溯上限**（能查多少天前）？ | N 的最终界 |
| **V5** | 分页总上限（`sportLength`/`dataLength`）**是否会截断一次大批量补拉**？ | 决定"一次打开能否补全 N 天" |
| **V6** | 设备**断电/换绑/解绑后缓冲是否清空**？同步后缓冲是否被覆盖？ | 决定 N 的时点依赖（非"固定 N 天"） |

> ⚠️ **本节全部标「推定」** —— 未取真机实测前，**N 不得作为已成立参数记入任何观测率结论**。

## 二、观测率模型与敏感性矩阵（**推定**）

### 2.1 定义与推导

- `λ`=打开频次（**次/周**）｜`N`=设备留存窗口（**天**）｜`p`=真实佩戴率（=`A3_true`）｜`s`=**单次前台同步成功率**（客户打开即视为尝试）
- `T`=台账应戴天；`N_true=p·T`；`N_obs`=实际回捞到的有效佩戴天；**A3 观测率** `f ≡ N_obs / N_true`（**条件于实戴**，与既有 metric-impact §1.2 一致）
- **补拉机理**：某实戴日 `d` 被观测 ⟺ 存在一次成功打开落在 `[d, d+N]`（该日数据仍在设备缓冲内）

**① 保守模型（Model C · 规律打开 · 无重试）**：每 N 天内恰好一次相关打开 → `C(λ,N)=min(1,λN/7)`（`λN≥7 ⟺ 打开间隔 7/λ≤N`）→ `f_C = s·min(1,λN/7) ≤ s`（**上限即 `s`**）。
**② 随机模型（Model O · 泊松重试有效）**：窗内成功打开数 ~ Poisson((λ/7)Ns) → `f_O = 1 − exp(−(λ/7)Ns)`（**可超 `s`，趋近 1**）。
> **两模型在打开稀疏（λN/7≤1）时一致，分歧在 λN/7>1；真实客户介于其间。本轮以 Model C 为判据下界（不夸大），Model O 为上包络。**

### 2.2 敏感性矩阵（`f*` ≈ 91.5% 为判定线；中值取 `s`=0.90，推定）

| **Model C（保守）`f=s·min(1,λN/7)`** | N=7 | N=14 | N=30 |
|---|---|---|---|
| λ=7 / 3 / 2 / 1 | 0.900 | 0.900 | 0.900 |
| λ=0.5 | 0.450 | 0.900 | 0.900 |
| λ=0.25 | 0.225 | 0.450 | 0.900 |

> **跨 `f*`=0.915 的组合：无**（`s`=0.90 < 0.915，全表 ≤ `s`）。**注意**：所有 `λN ≥ 7`（= 打开间隔 ≤ N 天）的单元格**都顶到 `s` 天花板** —— **补拉一旦生效（覆盖=1），λ 就完全退出**，瓶颈只剩 `s`。

| **Model O（随机重试上包络）`f=1−e^(−(λ/7)Ns)`**，`s`=0.90 | N=7 | N=14 | N=30 |
|---|---|---|---|
| λ=7 | **0.998 ✅** | **1.000 ✅** | **1.000 ✅** |
| λ=3 | **0.933 ✅** | **0.996 ✅** | **1.000 ✅** |
| λ=2 | 0.835 | **0.973 ✅** | **0.999 ✅** |
| λ=1 | 0.593 | 0.835 | **0.979 ✅** |
| λ=0.5 | 0.362 | 0.593 | 0.855 |
| λ=0.25 | 0.195 | 0.362 | 0.618 |

> ✅ = 跨过 0.915。**Model O 下跨线条件 ≈ `λN ≳ 20`**（`s`=0.90：`λN > ln(1/0.085)/s ≈ 19.2`）。

### 2.3 跨线判据（两模型合成一句话）

```
跨 f* ≈ 91.5%  ⟺  (Model C) s > 0.915 AND 打开间隔 7/λ ≤ N
                或 (Model O) (λ/7)·N·s > 2.466，即 λN ≳ 20（s=0.90）
```

| `s`（单次同步成功率） | Model C 跨线单元格 |
|---|---|
| 0.80 / 0.85 / 0.90 | **无** |
| 0.92 | 所有 `λN ≥ 7` 单元格（**勉强**，裕度 0.005） |
| 0.95 | 所有 `λN ≥ 7` 单元格（稳健） |

> 🔴 **核心判定**：**补拉把"必须每天打开"降为"每 N 天内打开一次"，使 λ ≤ 1 客户也能顶到上限；但"能否跨 `f*`"最终卡在 `s`（保守）或 `λN`（乐观）。`N` 与 `s` 均未取证 → 本轮结论为"条件性"：在 `N ≥ 打开间隔` 且 `s > 0.915` 时可跨，否则不跨。**

## 三、补拉 vs 不补拉：观测率提升对照（`s`=0.90）

**不补拉基线（原"打开才采当天"）**：`f₀ = s · min(1, λ/7)`（≈打开率 × 同步成功率）。**补拉**：`f_C = s · min(1, λN/7)`。

| λ（次/周） | 不补拉 `f₀` | 补拉 N=7 | N=14 | N=30 | **提升（N=7）** |
|---|---|---|---|---|---|
| 7（每日开） | **0.900** | 0.900 | 0.900 | 0.900 | **+0.000** |
| 3 | 0.386 | 0.900 | 0.900 | 0.900 | **+0.514** |
| 2 | 0.257 | 0.900 | 0.900 | 0.900 | **+0.643** |
| 1 | 0.129 | 0.900 | 0.900 | 0.900 | **+0.771** |
| 0.5 | 0.064 | 0.450 | 0.900 | 0.900 | **+0.386** |
| 0.25 | 0.032 | 0.225 | 0.450 | 0.900 | **+0.193** |

> **提升幅度**：**每日打开者几乎无增益（两者都顶 `s`）；打开越稀疏增益越大（λ=1 时 +0.77）。**
> **是否翻转"不过阈值"结论？** **Model C（保守）下：不翻转** —— 上限同为 `s`=0.90 < 0.915，**补拉抹掉 λ 依赖，但没抬高天花板**；**Model O（随机）下：可翻转** —— λ≥2 且 N≥14、或 λ≥1 且 N≥30 等组合可跨。
> **→ 诚实结论：补拉"必然跨 `f*`"不成立；"可能跨"成立，且有明确前提（N、s）。没有真机 `s` 与厂商 `N` 前，不得写成"补拉可让 A3 达标"。**
> **对照基线澄清**：brief §八 的「路径A 采率 0.80~0.90 ≤ `f*`」对应 **λ≈7（乐观每日打开）**，非典型客户；**典型客户 λ≤3 → 不补拉 `f₀` 低至 0.13~0.39，远低于 `f*`**。

## 四、`isWear` 的双刃性分析

**文档事实**（§5.11 `getHealthDetail()`，**文档自证、待真机复核**）：`isWear`：`1=佩戴 / 0=脱腕 / (-1,255)=无效`。

- **好的一面**：提供逐点/逐日佩戴状态 → 使"未佩戴"与"佩戴"**可区分**（原 metric-impact §1.5 **G1 条件被解除**的前提）；可支撑"佩戴即算"口径（口径乙），避免把"戴了但无有效读数"计 0。
- **风险面（双刃）**：

| 问题 | 后果 |
|---|---|
| **`(-1,255)` 无效值域太宽**（257 个值）→ **无法区分"传感器失败/固件异常/未初始化"与"脱腕"** | 当"脱腕" → **设备异常判成"客户没戴" = 冤枉客户**（技术性缺失被当行为性） |
| 当"佩戴" → 分子虚高（**粉饰**） | 方向单一、无告警 |
| 无效值与"无记录"叠加（A6 未解） | **三态无法互辨**：没戴 / 设备没记 / 同步失败 |

- **归类与处置（明确）**：`isWear=1` → 佩戴（正常）；`isWear=0` → 脱腕（行为性缺失，可扣分）；`isWear=(-1,255)` → **技术性缺失（设备/传感器层不可得）→ `applicable=False`（不扣分）**。
> **判定**：`(-1,255)` 属 **技术性缺失（G7 家族）** —— 既非"客户可控制的行为性"，也非"未同意佩戴的结构性"，而是**设备侧不可得、可缓解（靠排查）**。**处置：一律不判行为性缺失（宁可少扣、不可错扣）**。**必须向厂商确认 `(-1,255)` 触发条件，并要求"设备异常/传感器失败"原因码**，以把"设备异常"与"客户脱腕"分开。

## 五、A3 口径建议 + 三重缺失判定表

### 5.1 A3 分子/分母定义（补拉模式下）

| 项 | 定义 | 与既有口径的关系 |
|---|---|---|
| **分母** `T` | **台账应戴天** = 设备台账 `绑定日→解绑日` 日历天数，扣除 `pause_period` 暂停期（住院/洗浴/桑拿） | **不变**（沿用 metric-impact §1.6）。**不得用"数据存在性"当分母**（否则 A3 恒 1.0、静默虚高；属「缺失不得被平均或清洗」原则 *既有原则、复现于本处*） |
| **分子** `N_obs` | 补拉回来的**历史天** + 当次同步的**当天**中判定为"**有效佩戴天**"的天数 | **新增（相对不补拉）**：历史天**计入分子** —— 与当日天**同样是"有效佩戴"的证据**，不得因"不是当天采的"而排除 |
| **有效佩戴天判定** | `isWear=1` 且有效测量时长 ≥ 阈值（`getX04HealthIntervals` 可支撑） | 阈值待校准（既有 D2 方案） |

### 5.2 三重缺失判定表（**必须分开**）

| # | 缺失类型 | 识别信号 | 性质 | **A3 处置** |
|---|---|---|---|---|
| **①** | **客户未同意佩戴** | 意愿字段 = 暂不佩戴 | **结构性** | **`applicable=False`、权重重归一、不扣分** |
| **②** | **客户同意但长期不戴** | 有前置有效记录 ∧ **有脱腕记录 `isWear=0` 或长段规律性零数据** ∧ 无技术性信号 | **行为性** | **缺失天计 0（扣分）** —— 唯一应扣的一类 |
| **③** | **设备/同步问题取不到**（含 `isWear=(-1,255)`/未同步/打开间隔>N/A6 静默不返回） | 有前置有效记录 ∧ 无 `device_unbind` ∧ 断点突变 | **技术性** | **`applicable=False`、不扣分**（并入 G7 处置） |
| （附） | **合规摘除**（住院/洗浴/桑拿按说明书摘下） | 有 `pause_period` 申报 | 合规摘除（G8） | **暂停期从分母剔除** + 不扣分 |

> **判据字段**：`device_unbind`/`unbind_reason`/`pause_period`/`charge_reminder_sent_at` 为**硬需求**；`app_uninstall` **降级为"待厂商确认"**（App 无法上报自身被卸载）。与瑞思 §4.3-2 自我订正一致，**本处不改动**。

### 5.3 **关键结论：补拉能否把 A3 从「结构性不可观测」升为「可算准」？**

> **答：升为「条件可算」，不能升为「无条件算准」。**

| 阻塞项 | 状态 | 对 A3 的影响 |
|---|---|---|
| **N（留存窗口）未定** | ❓ 待厂商 | 若客户 N 天内一次都不打开 → 该段数据**永久丢失** → **结构性不可观测（不可缓解）** |
| **s（单次同步成功率）未定** | ❓ 待实测 | 决定观测率天花板；`s ≤ 0.915` 时保守模型永不跨 `f*` |
| **A6（无数据语义）未解** | ❓ 待厂商 | 静默不返回 → 无法区分"没戴"与"设备没记/同步失败" → **结构性不可观测成分残留** |

**→ 结论**：**补拉把"技术性缺失"大幅减少、把观测率上限从"打开率（≈0.85）"抬到 `s`，"日常断连"类缺口基本可被事后补齐**；**但"结构性不可观测"成分（N 窗口外的数据、A6 的静默缺失）无法消除**。故 A3 定位：
- **满足条件时**（`N ≥ 打开间隔` ∧ `s > 0.915` ∧ A6 有"无记录"标记）→ **A3 可算准、进 AS_refund 判定**；
- **不满足时** → **整维 `applicable=False`、权重重归一**（**依从性模型退化为三维 `0.80·A1 + 0.20·A4`**，与 PRD §2.8.5 选项 B 连带后果一致）。

## 六、A6 未解风险下的保守记账

**问题**：厂商文档**未明写**"无数据时返回'无记录'标记还是静默不返回"（**A6 仍未解**）。补拉模式下，若某天**静默不返回**，我方**无法区分**"客户没戴"与"设备没记/同步失败"。

**对"不补 0"原则与 A3 计分的含义**：PRD P0-10 要求"标记空缺、不得补 0"，其**前提是系统"知道"这一天应有数据但缺失**。静默不返回 → **P0-10 的"不补 0"在语义层静默失效**（缺失天不进分母 = 把分母扔掉 → A3 虚高、无告警）。

### 保守记账方式（宁可判技术性缺失、不判行为性缺失）

| # | 规则 | 理由 |
|---|---|---|
| **C1** | **不得补 0**（沿用 P0-10） | 无数据 ≠ 客户没戴 |
| **C2** | 该天标 **`missing_reason=unknown`**，**优先归技术性缺失**（不判行为性） | 证据不足时既不罚客户、也不奖自己（双面原则） |
| **C3** | **未知缺失天不与"有效佩戴天"同分（不进分子）** | 不奖自己 |
| **C4** | **分母 `T` 仍按台账应戴天保留，不得逐天剔除** | 守住「缺失不得被平均或清洗」原则 —— **禁止用"我没采到"当"客户没戴"来洗分母** |
| **C5** | **设"未知缺失占比"门**：`unknown` 缺失占应戴天比例超阈值（建议初始 30%，待校准）→ **A3 整维 `applicable=False`、权重重归一** | **"不冤枉客户"的正确兜底** —— 用"整维退出"替代"逐天洗分母"，两原则同时满足 |
| **C6** | 评估页显式暴露「**原因未知缺口 N 天**」（措辞中性、不暗示已归因） | 至少不静默（P0-10 第 4 条验收的精神） |

> ⚠️ **风险提示**：若 A6 证实"静默不返回"且**无原因码**，C5 会**频繁触发** → **A3 长期 `applicable=False`** → **手环维度实质性退出判定链**。该后果**必须显式记录为"降级态"并留痕**，不得静默发生（沿用 metric-impact §1.5 关键推论）。

## 七、`f*` 与 `ΔAS` 复核

**7.1 `ΔAS = 0.286 × ΔA3` —— 成立 ✅**：`AS_refund = 0.571·A1 + 0.286·A3 + 0.143·A4`（**0.571+0.286+0.143 = 1.000 ✓**），0.286 = 0.20/(0.20+0.40+0.10) = 0.20/0.70（**三维归一** A1/A3/A4）→ `∂AS/∂A3 = 0.286` → **成立**。

**7.2 `f*` ≈ 91.5% —— 成立，但须标注其对应的真实合规水平**：`AS_obs = c·(0.714 + 0.286·f)`（设 `A1=A3_true=A4=c`）；令 `AS_obs=0.8` → `f* = (0.8/c − 0.714)/0.286`。

| 真实合规 `c` | **`f*`** | 备注 |
|---|---|---|
| 1.00 | 30.1% | 全达标客户 |
| 0.95 / 0.90 / 0.85 | 44.8% / 61.1% / 79.4% | — |
| **0.82** | **91.5%** | **本轮引用的 `f*`≈91.5% 对应 `c≈0.82`（临界客户，裕度 0.02）** |
| 0.81 / 0.80 | 95.7% / 100% | 几乎任何数据损失即翻车 |

> **复算**：`c=0.82` → `(0.8/0.82 − 0.714)/0.286 = 0.26161/0.286 = 0.9147 ≈ 91.5%` ✅
> **两处均成立**；**注意 91.5% 是 `c≈0.82` 这一临界客户的判据、非普适阈值** —— 引用时须带上 `c`。
